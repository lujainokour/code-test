# ربط دورات الطالب والشركة والإدارة

نُفذت الروابط الأربعة داخل النسخة المحلية من المشروع. الواجهات أصبحت تقرأ سجلات مشتركة فعلية في المتصفح، مع استمرار عينات العرض القديمة. الربط بين أجهزة أشخاص مختلفين ما زال يحتاج API وقاعدة بيانات ومصادقة على الخادم.

## تحديث 8 نوفمبر 2026

أصبحت جلسات المعلم مرتبطة بطلبات الطالب وقبول المعلم وإلغاء الحجز، وأصبحت طلبات الخدمات والمسودات مشتركة بين تبويبات المتصفح ومحفوظة بعد إغلاقها. دليل المواهب يستخدم معرف تواصل عامًا دون بريد الطالب في الصفحة العامة. تفاصيل الاستخدام والحدود ونتائج التحقق في [تقرير الإصلاحات الحالية](FIXES-2026-11-08.md). تبقى الخدمة محلية ولا تتصل بين أجهزة مختلفة.

## التشغيل

من مجلد المشروع:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/serve.ps1
```

افتح `http://127.0.0.1:8765/`. استخدم عنوان الموقع نفسه والمتصفح نفسه لكل الأدوار. الروابط الجديدة تستخدم التخزين المحلي المشترك بين تبويبات الأصل نفسه؛ لا تعتمد على فتح الملفات مباشرة أو تبديل المنفذ والعنوان أثناء الجولة.

## 1. فرصة الشركة ← تقديم الطالب ← تدريبه ← مراجعة الشركة

1. افتح `pages/auth/company-login.html` وسجّل دخول الشركة، ثم افتح `company-jobs.html` وأنشئ فرصة.
2. افتح لوحة الطالب، ثم مجموعة **Opportunities & messages** واختر **Opportunities & training**؛ الصفحة هي `pages/student/career.html`.
3. اختر الفرصة، واكتب سبب التقديم ثم **Apply locally**.
4. الطلب يظهر تحت **My applications & training**، وللشركة في `pages/company/company-applications.html` عند دخولها بحساب الشركة.
5. يمكن للشركة جدولة مقابلة أو قبول الطلب أو رفضه. الضيف لا يرى الطلبات الخاصة المرتبطة بالطلاب.
6. عند القبول، تظهر للطالب لوحة تدريب من أربع مهام، مع نص متطلبات الفرصة المحفوظ وقت التقديم.
7. الطالب يحدّث حالات المهام. بعد جعل المهام كلها **Done**، يحفظ رابط مستودع GitHub وملاحظات التسليم بواسطة **Submit project for company review**.
8. يظهر التسليم داخل بطاقة الطلب عند الشركة، التي تختار **Changes requested** أو **Completed**.
9. طلب التعديلات يظهر للطالب ويتيح إعادة التسليم؛ إكمال المراجعة يجعل التدريب للقراءة فقط. هذه المراجعة المحلية لا تجتاز مهام Python ولا تصدر شهادة المنصة.

لا يسمح بتقديم مكرر للفرصة نفسها، أو التقديم لفرصة أوقفتها الشركة، أو بدء التدريب قبل القبول. تُرفض التعديلات المبنية على نسخة تدريب قديمة بدل مسح تحديث الطرف الآخر.

## 2. الملف المحلي ← المعرض ودليل المواهب

1. افتح `pages/student/local-portfolio.html`.
2. يمكن اختيار مشروع التدريب الافتراضي بعد حفظه وإدراجه في الملف المحلي، أو مشروع سلّمته ضمن فرصة شركة.
3. في **Publish a student profile**، اكتب النبذة والمهارات، واختر المشاريع المراد عرضها.
4. وافق صراحة على نشر التفاصيل المحددة ثم اضغط **Publish selected profile**.
5. يظهر الملف في `pages/services/showcase.html`، وله صفحة عامة وروابط مشاريع، ويظهر أيضًا في `pages/company/company-talent.html`.
6. الشركة تستطيع فتح المشاريع والتواصل عبر صندوق الطالب المحلي.
7. **Unpublish profile** يزيل الملف من المعرض ودليل المواهب عند إعادة تحميلهما، مع إبقاء المشاريع الخاصة والطلبات والمحادثات.

لا يحدث نشر تلقائي. العرض العام يحتوي الاسم والنبذة والمهارات وروابط المشاريع المختارة، دون العمر أو البريد أو محادثات الحساب ودرجاته. تستخدم مساحة الشركة عنوان الحساب داخليًا لتوجيه الرسائل. المهارات والمشاريع موسومة بأنها مقدمة من الطالب، وليست ادعاء تحقق مستقل.

## 3. تعليق الطالب بالإدارة ← منع الدخول والوصول

1. الحساب الذي تستخدمه كطالب يُضاف إلى سجل الحسابات المحلي المشترك.
2. افتح `pages/admin/admin-students.html` واختر **الحساب المحلي الفعلي** ببريده. ما زالت هناك أسماء عينات منفصلة للتجربة.
3. افتح التفاصيل ثم إجراء التعليق، ووافق على نافذة التأكيد.
4. التعليق يمنع تسجيل الدخول، والوصول إلى سجلات الطالب، والتقديم، والرسائل، والنشر وتغييرات التعلم. صفحة الطالب المفتوحة في تبويب آخر تعرض حجب الوصول عند وصول تغيير التخزين.
5. الاستعادة من الإدارة تعيد الوصول دون حذف إنجازات الطالب أو طلباته أو تسليماته.

تعليق اسم عينة قديم لا يعلق شخصًا آخر يحمل اسمًا مشابهًا؛ الربط للحساب المحلي يعتمد على معرف الحساب والبريد. الإدارة نفسها ما زالت معاينة محلية؛ لا توجد سلطة أمنية على الخادم. صاحب المتصفح يستطيع تغيير تخزينه، لذلك هذه ليست حماية إنتاجية.

بيانات العرض موجودة في شاشات الدخول المناسبة تحت وسم Demo only. الحسابات الطلابية المسجلة تدعم الدخول مجددًا في المتصفح نفسه، وكذلك حساب الشركة المحلي. إدارة جلسات المنصة انتقلت إلى الأدمن، وروابط المعلم القديمة تحوّل إلى الإدارة. لا توجد مصادقة على الخادم.

## 4. رسائل الشركة ← صندوق الطالب ← رد الطالب

1. من ملف طالب منشور في دليل المواهب، أو من طلب تقديمه، تختار الشركة **Candidate Chat** أو تكتب له رسالة من نافذة التواصل.
2. رابط **Candidate Chat** يفتح محادثة المرشح المختار، بما فيه المرشح الجديد الذي لم تكن له محادثة مسبقًا.
3. الطالب يفتح **Company inbox** من قائمته؛ الصفحة هي `pages/student/messages.html`.
4. يرى الطالب محادثاته بحسب حسابه فقط، ويكتب الرد. الرد يظهر في صفحة رسائل الشركة.
5. الشركة تستطيع الرد من صفحتها الحالية. تتجدد المحادثات عند تغيّر التخزين في تبويب آخر أو الرجوع إلى التبويب؛ لا يُمسح نص طالب غير محفوظ بسبب تحديث خارجي.

النصوص تُعرض كنص آمن. هذه رسائل مشتركة بين المساحات في المتصفح نفسه، وليست بريدًا إلكترونيًا أو خدمة مراسلة بين أجهزة. قد تبقى محادثات العينات القديمة ظاهرة مع حساب العينة.

## أين نُفذ الربط؟

| الملف | مسؤوليته |
|---|---|
| `js/platform-store.js` | سجل الحسابات المشتركة، التعليق والاستعادة، الهوية المطلوبة للعمليات، والنشر الصريح للملف العام |
| `js/learning-storage.js` | ربط هوية الطالب بالسجل المشترك وفحص إتاحة الحساب عند قراءة سجلاته وكتابتها |
| `js/company-store.js` | الفرص، الطلبات الفعلية، التدريب والتسليم والمراجعة، والمحادثة المشتركة |
| `js/student-career.js` | واجهتا الفرص/التدريب وصندوق الشركات عند الطالب |
| `js/portfolio-publishing.js` | اختيار المشاريع والنشر والسحب من المعرض ودليل المواهب |
| `js/admin-student-data.js` | إظهار الحسابات المحلية الفعلية مع العينات وإدارة حالتها |
| `js/company-workspace.js` | عرض طلبات الطلاب وتسليماتهم ومراجعتها وروابط ملفاتهم ومحادثاتهم |
| `js/student-services-data.js` | إضافة الملفات المنشورة صراحة إلى بيانات المعرض العام |

المفتاح `codementor-platform-v1` يخزن السجل والنشر، والمخزن الحالي للشركة يحتفظ بسجلات الطلبات والتدريب والمحادثات. تبقى مساحة شركة واحدة محلية في هذا المتصفح؛ لا يمكن استبدال هويتها بشركة أخرى بعد وجود سجلات طلاب مرتبطة بها.

- فحص المراجع النهائي: **140 زيارة، 195 مرجعًا محليًا، دون ملفات مفقودة أو استثناءات JavaScript مسجلة**.

- تغييرات الكود تخص النسخة الرئيسية؛ نسخة `delivery/` المؤرشفة لم تُعدّل.

## كيف يصبح الربط بين مستخدمين على أجهزة مختلفة؟

هذا تصميم الخطوة التالية، ولم يُنفذ كخادم ضمن هذا التغيير:

| البيانات المركزية | دورها |
|---|---|
| Users / Roles / AccountStatus | هوية موحدة وصلاحيات وحالة تعليق يطبقها الخادم على كل طلب |
| Companies / Opportunities | ملكية الفرصة للشركة وإتاحتها للطلاب |
| Applications | ربط `studentId` بـ`opportunityId` وحالة التقديم والمقابلة |
| TrainingProjects / Tasks / Submissions / Reviews | تدريب ناتج عن طلب مقبول، وتسليم الطالب ومراجعة الشركة |
| PublicProfiles / PortfolioProjects | بيانات الطالب التي اختار نشرها فقط |
| Conversations / Participants / Messages | أعضاء المحادثة ورسائلهم وصلاحية القراءة والرد |

يوضع API أمام قاعدة البيانات الحالية بعد مراجعة مخططها، وتستبدل دوال التخزين المحلية بطلبات إلى هذا الـAPI مع الحفاظ على واجهات الصفحات. يتحقق الخادم من الهوية والتعليق وملكية الشركة ومشاركة المحادثة؛ لا يُعتمد على بريد يرسله المتصفح لإثبات الملكية. وتصبح تحديثات الحالة والتسليم معاملات متحققة من النسخة الحالية، مع إشعارات أو تحديث مباشر عند الحاجة.

لا توضع بيانات اتصال SQL Server أو أسرار الدفع أو البريد داخل JavaScript الواجهة. ربط SQL Server مباشرة بالصفحات لا يحقق المصادقة أو العزل بين المستخدمين.
